# Верификация таймингов транскрипта в источнике

**Дата:** 2026-08-06
**Статус:** одобрено, в реализации

## Проблема

Таймкоды Whisper — не акустические. На невнятных участках модель квантует
границы сегментов к целым секундам (замер: 62% границ на коротком клипе,
8–12% на часовых уроках), а систематическая ошибка границ достигает секунд.
Все задачи монтажа — наполнители, тишины, jump cuts, главы, монтаж по
смыслам, In/Out, рилсы — наследуют эти времена, поэтому резы и маркеры
попадают в середину фраз. Патчи в отдельных потребителях (снэп глав от
05.08.2026) — симптоматика: N точек интеграции, каждую можно забыть.

Cloud.ru Whisper не отдаёт пословные тайминги (`timestamp_granularities`
игнорируется — проверено живьём 17.07.2026), поэтому опора — измеренные
паузы ffmpeg silencedetect (±10мс). Текущая карта пауз (`d=0.5`) слишком
редкая: одна пауза на ~10.5с на часовом уроке, паузы короче 0.5с невидимы.

## Решение (одобренный вариант: коррекция в источнике)

Цель — границы фраз (не пословная точность). Политика для непроверяемых
границ: **метить и защищать** — времена не портим, флаг честный,
деструктивные операции на неподтверждённой границе не выполняются вслепую
(host-принцип «отклонять, а не клампить»).

### 1. Плотная карта краёв речи

`computeAudioPreprocess` (`timeline-transcribe.js:416`) получает второй
проход `silencedetect` с `d=0.15` и тем же адаптивным порогом, что и
основной. Результат — `audioAnalysis.silencesDense` (те же координаты
таймлайна, тот же формат `{startSec, endSec, durationSec}`). Существующий
`silences` (d=0.5) не меняется — на нём живёт резка тишин. Чанкование
и склейка offset'ов — через существующий `analyzeChunksInParallel`,
все 5 режимов транскрибации наследуют автоматически.

### 2. Верификация границ сегментов в источнике

Чистая функция `verifySegmentBoundaries(segments, silencesDense, opts)`
в `transcript-structure.js`. Вызывается один раз в конце `runFromPrep`
до `setTranscriptEntry` — единая точка для всех режимов.

Правило асимметричное — «никогда не сжимать речь»:
- **начало сегмента** снэпится к речевому онсету (конец плотной паузы):
  назад до 1.0с, вперёд до 0.25с;
- **конец сегмента** снэпится к речевому оффсету (начало паузы):
  вперёд до 1.0с, назад до 0.25с.

Каждая граница получает флаг `startVerified` / `endVerified` (boolean).
Инварианты: `startSec < endSec`, сегменты не пересекаются и не меняют
порядок; ломающий инвариант снэп откатывается (времена исходные, флаг
false). Граница, для которой в окне нет измеренного края речи, не
двигается и остаётся `false` — честно «проверить нечем».

Сводка в `entry.timingVerification = {verifiedPct, startsVerified,
endsVerified, total, at}` — для UI/диагностики.

Потребители (paragraphs, topics, главы, наполнители, jump cuts, монтаж,
In/Out) не меняются — наследуют исправленные времена.

### 3. Защита деструктивных операций

`refineCutBoundaries` (`deterministic-pipelines.js:2725`):
- предпочитает `silencesDense` обычным `silences`, если есть;
- новый строгий режим (`opts.strict`): интервал, чью границу не удалось
  подтвердить паузой в окне снэпа, исключается из плана реза с причиной;
  счётчик пропущенных возвращается вызывающему и виден в предложении
  до подтверждения пользователем.

### 4. Миграция и совместимость

- Поля аддитивные. Старые кэши без `silencesDense`/флагов = «не
  проверено» — поведение не хуже текущего.
- Импорт транскрипта из файла: если в payload есть
  `audioAnalysis.silencesDense` — переверификация при загрузке; нет —
  флаги false.
- Ripple/stale уже удаляют `audioAnalysis` целиком — плотная карта
  уходит вместе с ним; флаги сегментов сохраняются (ripple сдвигает
  точной арифметикой, корректность границ не меняется).
- Снэп глав в `chapterize` (05.08.2026) остаётся страховкой для старых
  кэшей без верификации.

### 5. Верификация результата

- Node-тесты `verifySegmentBoundaries` на живых данных (Nested Sequence
  02: silences + сегменты, граница 60.0 → онсет 57.787).
- Тесты плотного прохода (парсинг, merge чанков) и строгого режима
  `refineCutBoundaries`.
- Живой прогон: перетранскрибация Nested Sequence 02, метрика
  «граница сегмента → ближайший край речи» до/после.
- `npm test` (базлайн 1129) + `node --check` изменённых файлов.

## Не делаем (осознанно)

- Пословный forced alignment — следующий этап (облачный лифт); эта
  работа готовит ему посадочное место: alignment заполнит те же поля.
- Ремап `seg.words[]` при ripple — вне скоупа.
- Изменение параметров основного silencedetect (d=0.5) — резка тишин
  живёт как жила.
